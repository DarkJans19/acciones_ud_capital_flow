# Especificaciones SDD

Cada cambio funcional comienza con un spec. Debe describir problema, alcance,
actores, reglas, contratos, datos, seguridad, escenarios, pruebas, criterios de
aceptación, decisiones pendientes y trazabilidad al SAD.

## Índice

- [`0001-backend-foundation.md`](./0001-backend-foundation.md): bootstrap técnico.
- [`active-scope-traceability.md`](./active-scope-traceability.md): conciliación
  entre SAD, catálogo PDF actualizado y alcance activo.
- [`01-identity-security/requirements.md`](./01-identity-security/requirements.md):
  identidad, autenticación, MFA, perfiles, roles y sesiones.
- [`02-market-data/requirements.md`](./02-market-data/requirements.md): mercados,
  instrumentos, búsqueda, cotizaciones, históricos y difusión en tiempo real.

Usa [`_template.md`](./_template.md) y asigna un identificador estable. No marques
una decisión pendiente como aprobada sin evidencia del equipo. Los directorios de
módulos futuros se crean solo cuando su alcance haya sido priorizado.
